## Findings (verbatim, unedited)

1. R1-1 — BLOCKER — `harness/upstream016.py` loader; `harness/score.py` import block; `harness/make_manifest.py` coverage; `.gitignore`: The registered invocation does not prove that pinned `.py` bytes are the code executed. Ordinary imports and `spec.loader.exec_module()` consume ignored, unmanifested timestamp-valid `__pycache__/*.pyc` files; the current apparatus demonstrably loads cached bytecode for Study 017’s harness/witness modules and Study 016’s supposedly pinned verifier/writer, while origin checks still report the corresponding `.py`. Fix: use a stdlib-only bootstrap that hashes, compiles, and executes the exact source bytes read once; do not rely on ordinary import loading or `-B`, which still permits reading existing caches.

2. R1-2 — BLOCKER — `harness/PINS.json` `harnessPython`; `harness/score.py` imports/pin enforcement; `witness/sighting.py`; `witness/verify_witness.py`; `../016-policy-currency-anchor/harness/score.py` dependency enforcement: `PINS.json` claims `cryptography` and `rfc8785` are transitively pinned by Study 016, but Study 017 neither consumes Study 016’s dependency lock nor checks package versions, origins, or bytes. Those packages execute before the scorer reads or enforces pins, and the governing invocation accepts any CPython 3.12.11 environment. Fix: register and enforce dependency versions, distribution/code digests, and origins in the pre-import bootstrap before loading any study or cryptographic module.

3. R1-3 — BLOCKER — `harness/score.py` pin read and `pin_problems`; `harness/upstream016.py` `pinned_files`, `problems`, `_load_by_path`, and `_module_problems`; `PREREGISTRATION.md` §6: The `pinsRawSha256` bytes are not necessarily the pin mapping used to authenticate Study 016. The scorer parses one captured registry, but every upstream check rereads live `PINS.json`; replacing both `study016.files` digests in the parsed object still leaves `pin_problems()` empty. A post-marker change can therefore select different trust inputs than the attempt records. Fix: extract one immutable upstream-digest mapping from the exact stamped bytes and pass it through every load/check without rereading the registry.

4. R1-4 — BLOCKER — `witness/sighting.py` `build_sighting`; `witness/verify_witness.py` record routing; `witness/SPEC.md` §2; `harness/MATRIX.json` D-3 controls; `../016-policy-currency-anchor/PREREG-REVIEW.md` R1-6: `witnessKeyId` is outside the signed payload yet decides whether a record is verified or ignored. Relabeling only the honest conflicting record in `wit-one-honest` as a well-formed unpinned ID changes `fail:snapshot-conflicts-with-witnessed-head` to `pass` while the colluder still satisfies `minimumSightings: 1`; the same relabel converts `wit-split-view-caught` to pass. Thus the label does cause acceptance, directly falsifying D-3’s safety argument. Fix: authenticate record self-identification before pin routing—such as carrying the public key, deriving its ID, and verifying the signature before deciding membership—or reject unknown/non-verifying records; add relabel controls.

The synthetic tuple is faithful to the frozen currency function’s explicitly tested input surface (`../016-policy-currency-anchor/harness/tests/test_registry.py`), but not to the prior four-layer fixture. Fix: call it the same threat class, explicitly disclaim replication of 016’s full run, and make the valid “one sighting is the difference” comparison against the internally controlled `wit-partition-vacuous` cell.

6. R1-6 — MAJOR — `harness/score.py` `_collusion_structure`, `pair_reports`, and `decide`; `PREREGISTRATION.md` §§4 and 8: The promised collusion gate is neither sufficient nor verdict-gating. It checks a w1 signature, equal position, and unequal heads, but not equal/registered series, w1’s presence in each witness configuration, participation in the enforcement floor, uniqueness, or correspondence between each head and its presented snapshot; two signed records for different series validate as “equivocation.” `decide()` also ignores the validation result, so `validated: false` can coexist with `R1 holds`. The committed pair happens to be correct, but the claimed apparatus guarantee is absent. Fix: enforce all semantic invariants and make a false or unadjudicated pair pipeline-invalid.

7. R1-7 — MAJOR — `README.md` collusion discussion; `PREREGISTRATION.md` §§2, 4, and 9; `witness/SPEC.md` §§2 and 4; `harness/MATRIX.json` `wit-one-honest`; RFC 0011 Unresolved #9 and `rfcs/reviews/0011-round-3.md` RA-3: The study disclaims measuring independence but repeatedly calls independence “measured as a diff” and says a colluding witness satisfies “every clause.” `wit-one-honest` changes both the configured key set and delivered evidence by adding a conflicting sighting; it demonstrates the conditional effect of that record reaching the comparator, not organizational independence. Collusion also necessarily violates the independence/non-collusion clause. Fix: state that the cells illustrate why non-collusion may be required, replace “independence measured” with “one additional pinned conflicting sighting delivered,” and qualify “every clause” as every implemented clause except independence/non-collusion.
